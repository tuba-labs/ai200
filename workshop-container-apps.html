Oppsett for denne delen

Bruk ACR-registryet, ai200-api:v1 og terminalvariablene fra del 2. Ved ny terminal bruker du tilkoblingsblokken for registryet. Opprett Container Apps-ressursene nedenfor én gang. App Service-ressursene fra del 3 brukes ikke her.

# Sett navnet på Container App-en.
$ca = "ai200-api"
# Sett navnet på Container Apps-miljøet.
$caEnv = "ai200-env"
# Sett navnet på identiteten som skal hente Container App-ens image.
$caPullIdentityName = "ai200-ca-pull"

Gi appidentiteten lesetilgang til ACR

# Opprett en separat managed identity som appen kan bruke til image-pull.
az identity create --resource-group $rg --name $caPullIdentityName --location $location -o none
# Hent ressurs-ID-en til Container App-ens pull-identitet.
$caPullIdentityId = az identity show --resource-group $rg --name $caPullIdentityName --query id -o tsv
# Hent identitetens principal-ID for rolletildelingen i ACR.
$caPullPrincipalId = az identity show --resource-group $rg --name $caPullIdentityName --query principalId -o tsv
# Gi appidentiteten AcrPull på dette registryet.
az role assignment create --assignee-object-id $caPullPrincipalId --assignee-principal-type ServicePrincipal --role AcrPull --scope $acrId -o none

Opprett miljø og app

Bruk Consumption-profilen med minimum 0 og maksimum 2 replikaer. Oppsettet bruker live Log stream; det oppretter ikke et Log Analytics-workspace for historiske logger.

# Opprett et miljø med workload profiles, uten et workspace for historiske logger.
az containerapp env create --resource-group $rg --name $caEnv --location $location --enable-workload-profiles true --logs-destination none -o none
# Opprett appen med managed identity, ekstern ingress på port 8080 og 0–2 replikaer.
az containerapp create --resource-group $rg --name $ca --environment $caEnv --workload-profile-name Consumption --image "$login/ai200-api:v1" --user-assigned $caPullIdentityId --registry-identity $caPullIdentityId --registry-server $login --ingress external --target-port 8080 --cpu 0.25 --memory 0.5Gi --min-replicas 0 --max-replicas 2 --revisions-mode single -o none
# Hent Container App-ens eksterne vertsnavn.
$caFqdn = az containerapp show --resource-group $rg --name $ca --query properties.configuration.ingress.fqdn -o tsv
# Vis appens navn, opprettelsesstatus og eksterne vertsnavn.
az containerapp show --resource-group $rg --name $ca --query "{Name:name, State:properties.provisioningState, Host:properties.configuration.ingress.fqdn}" -o table

Kontrollpunkt: tilstanden er Succeeded. Helsesjekken gjøres i steg 1. Noter gruppe, appnavn, miljø, identitetsnavn og FQDN til del 5. Ved image-pull-feil kontrollerer du at identiteten har AcrPull på labregistryet; vent på at en ny rolle slår gjennom før du prøver opprettelsen igjen. Har du allerede disse ressursene, bruk navnene deres og hopp over opprettelsen.

Ny terminal: hent den eksisterende Container App-en

Bruk appnavnet fra denne delen før du fortsetter med del 5:

# Sett navnet på ressursgruppen som kommandoene skal bruke.
$rg = "ai200-d1"
# Sett navnet på Container App-en.
$ca = "ai200-api"
# Hent regionen til den eksisterende Container App-en.
$location = az containerapp show --resource-group $rg --name $ca --query location -o tsv

Microsoft Learn: image-pull med managed identity, opprette miljø og opprette Container App.

1. Undersøk miljø og ingress

Åpne appens Overview, Environment og Log stream, og kall helsesjekken:

# Kall Container App-ens helsesjekk og vis JSON-svaret.
Invoke-RestMethod "https://$caFqdn/health"

Forventet: JSON fra testappen. Noter miljøets nettverksvalg og forskjellen mellom appens inngangsadresse og containerens target port. Behold min 0 / maks 2 replikaer.

2. Opprett en ny revisjon

Aktiver Multiple revisions. Velg Edit and deploy og lag en revisjon med miljøvariabelen APP_VERSION=v2. Behold samme image slik at bare revisjonskonfigurasjonen endres. Finn begge revisjonsnavnene og vent til den nye er healthy.

3. Fordel trafikk og rull tilbake

Sett trafikk til 50 % på hver revisjon. Kall /health gjentatte ganger med curl.exe uten å gjenbruke cookies. Observer begge versjonene; få kall garanterer ikke en nøyaktig halvdeling. Rull deretter tilbake ved å sende all apptrafikk til v1-revisjonen. Bruk revisjonsnavnet du fant i forrige steg:

# Sett navnet på v1-revisjonen som skal få all trafikk.
$v1Revision = "DITT-V1-REVISJONSNAVN"
# Send 100 prosent av apptrafikken til v1-revisjonen.
az containerapp ingress traffic set --resource-group $rg --name $ca --revision-weight "$v1Revision=100" -o none
# Vis trafikkfordelingen mellom revisjonene.
az containerapp ingress traffic show --resource-group $rg --name $ca -o table

Bekreft at v2 ikke lenger får appens trafikk. Undersøk logger per revisjon. Microsoft Learn: fordele trafikk mellom revisjoner.

Rydd opp og forklar

I Revision management: velg den ubrukte revisjonen og Deactivate. Behold appen, miljøet og identiteten ai200-ca-pull til del 5. Hvis du avslutter her, slett disse tre ressursene fra ressursgruppens ressursliste. Behold ACR hvis del 6 skal bruke det. Forklar forskjellen mellom miljø, app, revisjon og replika.
