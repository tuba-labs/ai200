1. Opprett og les en testhemmelighet

I hvelvet: opprett demo-secret med verdien workshop-only-v1. Kjør:

# Les testhemmeligheten fra Key Vault og vis at oppslaget lyktes uten å vise verdien.
python labs/security/read_settings.py secret

Forventet: Secret read successfully: True og en versjons-ID. read_settings.py bruker DefaultAzureCredential og skriver aldri verdien. Forklar hvorfor data-plane-tilgang trengs i tillegg til rett til å administrere ressursen.

read_settings.py — vis fil og forklaring

Kildefil: labs/security/read_settings.py

"""Optional Azure exercise: read a demo secret and ordinary configuration via Entra ID."""

# Velg Key Vault-hemmelighet eller vanlig appkonfigurasjon.
import argparse
# Les tjenestenes endpoint fra miljøet.
import os

# Les nøkkel-/etikettverdier fra App Configuration.
from azure.appconfiguration import AzureAppConfigurationClient
# Bruk Entra-identitet, for eksempel Azure CLI-innlogging på egen maskin.
from azure.identity import DefaultAzureCredential
# Les hemmeligheter gjennom Key Vaults data-API.
from azure.keyvault.secrets import SecretClient

# Kjør ett oppslag mot den valgte tjenesten.
def main():
    # Opprett kommandolinjeparseren.
    parser = argparse.ArgumentParser()
    # Tillat bare de to oppslagstypene.
    parser.add_argument("mode", choices=["secret", "config"])
    # Les valgt oppslagstype.
    args = parser.parse_args()
    # Gjenbruk samme identitetsoppsett for begge tjenester.
    with DefaultAzureCredential() as credential:
        # Key Vault-operasjonen krever tilgang til hemmelighetens verdi.
        if args.mode == "secret":
            # Åpne klienten for ditt labhvelv.
            with SecretClient(vault_url=os.environ["KEY_VAULT_URL"], credential=credential) as vault:
                # Les gjeldende versjon av demo-secret.
                secret = vault.get_secret("demo-secret")
                # Vis bare at verdien ble lest, aldri selve hemmeligheten.
                print("Secret read successfully:", bool(secret.value))
                # Bruk versjons-ID til å observere rotasjon.
                print("Secret version:", secret.properties.version)
            # Avslutt etter Key Vault-oppslaget.
            return
        # Åpne klienten for vanlig konfigurasjon.
        with AzureAppConfigurationClient(
            # Bruk App Configuration-endpoint og den samme Entra-identiteten.
            base_url=os.environ["APP_CONFIG_ENDPOINT"], credential=credential
        # Lukk konfigurasjonsklienten etter bruk.
        ) as config:
            # Les akkurat nøkkelen og miljøetiketten som ble opprettet i portalen.
            setting = config.get_configuration_setting(key="Workshop:Mode", label="lab")
            # Vis den vanlige konfigurasjonsverdien i terminalen.
            print("Workshop mode:", setting.value)


# Start bare når filen kjøres direkte.
if __name__ == "__main__":
    # Kjør valgt konfigurasjonsoppslag.
    main()

2. Roter ved å opprette ny versjon

Legg til ny versjon av demo-secret med verdien workshop-only-v2. Kjør oppslaget igjen og sammenlign versjons-ID. Undersøk forskjellen på en versjonsbundet og en versjonsløs URI. Beskriv hvordan en app som cacher verdien må få den oppdatert.

3. Gi appen egen tilgang

  1. Aktiver system-assigned identity på Function App-en.
  2. Gi appidentiteten Key Vault Secrets User på labhvelvet.
  3. Legg app setting DEMO_SECRET til Function App-en med referansen under. Lagre og kontroller referansestatus.
  4. Kall configuration-funksjonen med Get Function URL. Forventet: secret_configured=true.
# La Azure hente siste versjon av demo-secret gjennom en versjonsløs Key Vault-referanse.
@Microsoft.KeyVault(SecretUri=https://DITT-HVELV.vault.azure.net/secrets/demo-secret/)

Plattformen løser referansen. Koden leser miljøvariabelen. Oppdateringer kan være forsinket av referansens cache; følg dokumentert refresh eller endre appkonfigurasjonen hvis du skal teste ny henting.

Rydd opp og forklar

Fjern først appens DEMO_SECRET-setting med de eksisterende appnavnvariablene fra del 14. $functionGroup er appens gruppe ai200-d3, selv om hvelvet ligger i ai200-d4:

# Fjern Key Vault-referansen fra Function App-ens innstillinger.
az functionapp config appsettings delete --resource-group $functionGroup --name $functionApp --setting-names DEMO_SECRET -o none
# Fjern KEY_VAULT_URL fra denne terminalen.
Remove-Item Env:KEY_VAULT_URL -ErrorAction SilentlyContinue

Slett deretter labhvelvet, Function App-en og dens dedikerte Storage-konto fra del 14; ingen senere deler bruker disse ressursene. Et slettet Key Vault kan ha soft delete; ikke purge for å gjenbruke et navn. Forklar forskjellen mellom brukeridentiteten under utvikling og appidentiteten under drift.
