Bygger på: 14. Bygg og publiser en HTTP Function.

Gjennomføringstiden er ikke målt. Sett av tid til å forklare valgene og prøve egne varianter. Følg klargjøringen i denne delen før oppgavene. Python-øvelsene bruker samme .venv i prosjektroten. Start kommandoene i prosjektmappen du åpnet i IntelliJ, der ikke annet er angitt.

Bruk egne labressurser og rydd opp etter bruk. Kostnadsveiledning (valgfritt).

Før du starter

Bruk en egen Key Vault med Azure RBAC og nettverkstilgang fra maskinen, og Function App-en fra workshop 14. Gi din bruker Secrets Officer for å opprette testhemmeligheten; appen får en egen leserolle. Ha Azure CLI innlogget.

.\.venv\Scripts\Activate.ps1
python -m pip install -r labs/security/requirements.txt
az login
$env:KEY_VAULT_URL = "https://DITT-HVELV.vault.azure.net/"

1. Opprett og les en testhemmelighet

I hvelvet: opprett demo-secret med verdien workshop-only-v1. Kjør:

python labs/security/read_settings.py secret

Forventet: Secret read successfully: True og en versjons-ID. Skriptet bruker DefaultAzureCredential og skriver aldri verdien. Forklar hvorfor data-plane-tilgang trengs i tillegg til rett til å administrere ressursen.

2. Roter ved å opprette ny versjon

Legg til ny versjon av demo-secret med verdien workshop-only-v2. Kjør oppslaget igjen og sammenlign versjons-ID. Undersøk forskjellen på en versjonsbundet og en versjonsløs URI. Beskriv hvordan en app som cacher verdien må få den oppdatert.

3. Gi appen egen tilgang

  1. Aktiver system-assigned identity på Function App-en.
  2. Gi appidentiteten Key Vault Secrets User på labhvelvet.
  3. Legg app setting DEMO_SECRET til Function App-en med referansen under. Lagre og kontroller referansestatus.
  4. Kall configuration-funksjonen med Get Function URL. Forventet: secret_configured=true.
@Microsoft.KeyVault(SecretUri=https://DITT-HVELV.vault.azure.net/secrets/demo-secret/)

Plattformen løser referansen. Koden leser miljøvariabelen. Oppdateringer kan være forsinket av referansens cache; følg dokumentert refresh eller endre appkonfigurasjonen hvis du skal teste ny henting.

Rydd opp og forklar

Fjern appens DEMO_SECRET-setting, og slett hvelv/Function App når de er ferdig brukt. Et slettet Key Vault kan ha soft delete; ikke purge for å gjenbruke et navn. Forklar forskjellen mellom brukeridentiteten under utvikling og appidentiteten under drift.
