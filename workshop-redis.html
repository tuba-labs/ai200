Caching og invalidering med Managed Redis

Koble Python til Managed Redis og øv på cache hit, miss, utløp og eksplisitt invalidering.

På denne siden

Klargjør før økten 1. Koble til sikkert 2. Hit, miss og utløp 3. Knytt operasjonene til applikasjonen Rydd opp Pensum og kilder

Før første workshop: Følg oppsettet for å hente og åpne prosjektet og klargjøre verktøyene før du kjører kommandoene på denne siden.

Gjennomføringstiden er ikke målt. Sett av tid til å forklare valgene og prøve egne varianter. Følg klargjøringen i denne delen før oppgavene. Python-øvelsene bruker samme .venv i prosjektroten. Start kommandoene i prosjektmappen du åpnet i IntelliJ, der ikke annet er angitt.

Bruk egne labressurser og rydd opp etter bruk. Kostnadsveiledning (valgfritt).

Klargjør før økten

Ha en Azure Managed Redis-labinstans klar med Enterprise clustering, TLS og en labnøkkel. Hvis du skal ta workshop 13, må RediSearch velges ved opprettelsen, med en tier som støtter modulen og NoEviction. Modulen kan ikke legges til senere. En arrangør kan klargjøre en delt labinstans.

1. Koble til sikkert

.\.venv\Scripts\Activate.ps1
python -m pip install -r labs/redis/requirements.txt
$env:REDIS_HOST = "DITT-REDIS-ENDPOINT"
$env:REDIS_PORT = "10000"
$env:REDIS_KEY = "DIN-LAB-NOKKEL"

Les tilkoblingen i demo.py. Den bruker TLS og en gjenbrukt klient. Enterprise clustering gir ett logisk endepunkt til den vanlige Redis-klienten; OSS clustering krever en cluster-klient.

2. Hit, miss og utløp

python labs/redis/demo.py cache

Forventet: først en miss, så en hit med positiv TTL, deretter miss etter invalidation og miss etter utløp. Skriptet sletter bare sin egen nøkkel. Kjør på nytt og sammenlign. Finn GET, SET med EX, DELETE og TTL i koden.

3. Knytt operasjonene til applikasjonen

Tegn rekkefølgen for cache-aside: GET, databaseoppslag ved miss, SET med TTL. Beskriv deretter hva en dokumentoppdatering skal invalidere. La nøkkelen inneholde søkeområde og dataversjon. Sammenlign kort TTL med eksplisitt invalidation; de løser ulike deler av problemet.

Rydd opp

Behold instansen bare til workshop 13 hvis du skal fortsette. Fjern REDIS_KEY fra terminalen, og slett labinstansen når du er ferdig.
