Oppsett for denne delen

Bruk registryet med ai200-api:v1 og terminalvariablene fra del 2. Har du åpnet en ny terminal, bruk tilkoblingsblokken for det eksisterende registryet. Opprett App Service-ressursene nedenfor én gang.

# Lag et globalt unikt navn på den nye webappen.
$web = "ai200-web-" + (New-Guid).ToString("N").Substring(0, 12)
# Sett navnet på Linux-planen til webappen.
$plan = "ai200-linux"
# Sett navnet på identiteten som skal hente webappens image.
$webPullIdentityName = "ai200-web-pull"

Opprett identitet, Linux-plan og webapp

Identiteten får AcrPull på ditt labregistry. Den brukes av App Service til å hente imaget uten registry-passord. Rolletildelingen krever tilgangen beskrevet i Kom i gang.

# Opprett en separat managed identity som appen kan bruke til image-pull.
az identity create --resource-group $rg --name $webPullIdentityName --location $location -o none
# Hent ressurs-ID-en til webappens pull-identitet.
$webPullIdentityId = az identity show --resource-group $rg --name $webPullIdentityName --query id -o tsv
# Hent identitetens principal-ID for rolletildelingen i ACR.
$webPullPrincipalId = az identity show --resource-group $rg --name $webPullIdentityName --query principalId -o tsv
# Gi appidentiteten AcrPull på dette registryet.
az role assignment create --assignee-object-id $webPullPrincipalId --assignee-principal-type ServicePrincipal --role AcrPull --scope $acrId -o none
# Opprett en Linux App Service-plan på B1-nivå i valgt region.
az appservice plan create --resource-group $rg --name $plan --location $location --is-linux --sku B1 -o none
# Opprett webappen med ACR-imaget og bruk den tildelte identiteten til image-pull.
az webapp create --resource-group $rg --plan $plan --name $web --container-image-name "$login/ai200-api:v1" --assign-identity $webPullIdentityId --acr-use-identity --acr-identity $webPullIdentityId -o none
# Sett WEBSITES_PORT til 8080 slik at App Service sender trafikk til riktig containerport.
az webapp config appsettings set --resource-group $rg --name $web --settings WEBSITES_PORT=8080 -o none
# Aktiver lagring av containerlogger i App Service.
az webapp log config --resource-group $rg --name $web --docker-container-logging filesystem -o none
# Hent webappens vertsnavn til helsesjekken.
$webHost = az webapp show --resource-group $rg --name $web --query defaultHostName -o tsv
# Vis webappens navn, kjøretilstand og vertsnavn.
az webapp show --resource-group $rg --name $web --query "{Name:name, State:state, Host:defaultHostName}" -o table

Kontrollpunkt: webappen vises som Running. Noter appnavn, vertsnavn, plan og identitetsnavn. Opprettelsen bruker et nytt appnavn hver gang; hopp over opprettelseskommandoene hvis appen allerede finnes. Ved ny terminal setter du navnene til de eksisterende verdiene. Plan B1 har løpende kostnad; kontroller valget i portalen før du fortsetter.

Microsoft Learn: opprette webapp med ACR og managed identity og containerport og konfigurasjon.

1. Få containeren i gang

  1. Åpne webappen i portalen → Identity → User assigned. Finn identiteten ai200-web-pull du nettopp koblet til appen. I ACR → Access control (IAM) → Role assignments finner du dens AcrPull-rolle.
  2. Under Environment variables kontrollerer du WEBSITES_PORT=8080. CLI-oppsettet over bruker klassisk Linux custom-container-konfigurasjon.
  3. Kall helsesjekken under og åpne Log stream i portalen. Vent på første oppstart. Ved image-pull-feil: kontroller identitet, rolle og taggen ai200-api:v1. En ny rolletildeling kan bruke litt tid på å slå gjennom; start da appen på nytt når rollen er tilgjengelig.
# Kall webappens helsesjekk og vis JSON-svaret.
Invoke-RestMethod "https://$webHost/health"

Forventet: JSON fra testappen og oppstartslogger.

2. Send konfigurasjon til containeren

Legg til WORKSHOP_MODE=review under Environment variables. Lagre, vent på restart og kall /health igjen. Forventet: mode blir review, uten nytt image. Finn appens konfigurasjonsendring og skill den fra en image-oppdatering.

3. Lever en testhemmelighet

Opprett app setting DEMO_SECRET=workshop-only og lagre. Dette er en offentlig øvingsverdi. Kall /health: secret_configured skal være true, mens selve verdien aldri returneres. Undersøk hvordan App Service lagrer og leverer innstillinger til containeren. Oppdater verdien og bekreft at samme image fortsatt brukes.

I workshop 19 lærer du å erstatte en lagret hemmelighet med en Key Vault-referanse og managed identity.

Rydd opp

I portalen: åpne ressursgruppen for øvelsen, marker webappen, planen ai200-linux og identiteten ai200-web-pull, velg Delete og kontroller navnene før du bekrefter. Behold ACR til del 4–6 er ferdige. Slett planen også; den kan fortsatt koste etter at webappen er slettet. Forklar hvorfor en miljøvariabel og en hemmelighet ikke trenger et eget image.
