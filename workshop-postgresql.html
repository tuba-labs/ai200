Klargjør før økten

Ha en liten Azure Database for PostgreSQL Flexible Server klar i en labgruppe, med TLS og nettverkstilgang fra din maskin. Opprett databasen workshop. Tillat utvidelsen vector i serverparameteren azure.extensions. Bruk en databasebruker med rett til å opprette labtabellen.

1. Koble til med Python

Start i prosjektroten. Hent tilkoblingsinformasjonen fra Connect i portalen. PGCONNINFO er en lokal miljøvariabel; behold sslmode=require og legg ikke passordet i filene.

.\.venv\Scripts\Activate.ps1
python -m pip install -r labs/data/requirements.txt
$env:PGCONNINFO = "host=DIN-SERVER.postgres.database.azure.com port=5432 dbname=workshop user=DIN-BRUKER password=DITT-PASSORD sslmode=require"
python labs/data/postgres_client.py setup
python labs/data/postgres_client.py query

Forventet: dokument 2 og 1. Finn de parameteriserte verdiene i postgres_client.py og forklar hvorfor SQL og data sendes separat.

2. Mål og gjenbruk forbindelser

python labs/data/postgres_client.py compare

Skriptet sammenligner ti nye forbindelser med ti spørringer via en liten klientpool. Gjenta og noter variasjonen. Tilkoblingslatens, nettverk og oppvarming påvirker resultatene. Undersøk min_size/max_size og hvorfor hver prosess trenger sin egen pool.

3. Undersøk Azure-flaskehalser

  1. Åpne Metrics for CPU, minne, aktive forbindelser og lagrings-I/O. Kjør compare igjen og noter hva en så liten last faktisk kan vise.
  2. Undersøk Compute + storage og PgBouncer. Velg et foreslått alternativ for mange samtidige oppslag og begrunn CPU/minne/lagring. Gjennomfør en endring bare på din labserver hvis øvelsen trenger den.
  3. På en tier med innebygd PgBouncer: aktiver den, bruk port 6432 i PGCONNINFO og kjør query/compare på nytt. Hvis tier-en ikke støtter det, bruker du klientpoolen og forklarer skillet.

Kombiner målingene med EXPLAIN-planen fra workshop 7. En liten datasamling er ikke en representativ kapasitetsmåling.

Rydd opp

Remove-Item Env:PGCONNINFO -ErrorAction SilentlyContinue
