Bygger på: 14. Bygg og publiser en HTTP Function.

Gjennomføringstiden er ikke målt. Sett av tid til å forklare valgene og prøve egne varianter. Følg klargjøringen i denne delen før oppgavene. Python-øvelsene bruker samme .venv i prosjektroten. Start kommandoene i prosjektmappen du åpnet i IntelliJ, der ikke annet er angitt.

Bruk egne labressurser og rydd opp etter bruk. Kostnadsveiledning (valgfritt).

Før du starter

Bruk den publiserte Function App-en fra workshop 14. Opprett et Event Grid custom topic i labgruppen. Finn topic endpoint og en labnøkkel. Koden har et anonymt event-hook-endepunkt som bare logger testhendelser og kan returnere en kontrollert feil.

.\.venv\Scripts\Activate.ps1
python -m pip install -r labs/integrations/requirements.txt
$env:EVENTGRID_ENDPOINT = "DITT-TOPIC-ENDPOINT"
$env:EVENTGRID_KEY = "DIN-LAB-NOKKEL"

1. Lag et filtrert abonnement

På topic-et: opprett Event Subscription med Event Grid Schema og Web Hook https://DIN-APP.azurewebsites.net/api/event-hook. Koden svarer på valideringshendelsen. Filtrer event type AI200.DocumentCreated, subject begins with documents/ og ends with .txt. Sett retry-policy til for eksempel 10 forsøk og 30 minutter TTL.

2. Publiser egne hendelser

python labs/integrations/publish_event.py

Forventet: bare note.txt kommer til webhooken. Finn event-id og subject i Function-loggene. Skriptet sender både en .txt- og en .csv-hendelse; kontroller at avvisningen skyldes filteret. Sammenlign en egen hendelse med BlobCreated fra en Azure-kilde.

3. Test levering etter feil

Sett app setting FAIL_EVENTS=true på Function App-en og vent på restart. Publiser igjen. Finn HTTP 503 og leveringsfeil i Event Grid-metrikkene. Sett FAIL_EVENTS=false, og vent på retry. Noter event-id ved vellykket levering. Retry har backoff og skjer ikke øyeblikkelig; behold abonnementet gjennom den konfigurerte perioden. Forklar hvorfor mottakeren må tåle duplikater og hva som skjer ved utløpt TTL.

Rydd opp

Slett abonnement/topic, fjern FAIL_EVENTS og EVENTGRID_KEY, og behold Function App-en bare hvis workshop 19 bruker den. Kontroller at retry-testen ikke fortsetter mot en app som skal slettes.
