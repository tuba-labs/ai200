Glossary

Short definitions for the terminology used in the core path.

Reference · use as needed

Application and AI

RAG
Retrieval-augmented generation: retrieve relevant reference text, then give it to a model as context for answering. Retrieval and generation are separate operations.
Chunk
A bounded piece of a manual. Its source ID, product, manual and chunk index remain attached so an answer can show evidence.
Embedding
A numeric representation used to compare text. This workshop uses 1536 values from one shared Azure embedding deployment.
Vector similarity
A way to rank embeddings by distance. The SQL operator <=> is cosine distance; smaller distance means a closer match.
Grounding
Using supplied evidence to support an answer. A citation lets the participant inspect the evidence; it does not guarantee the model's reasoning is correct.
Migration / Flyway
A versioned database schema change and the tool that applies/records it. Flyway is not an ORM and does not create your Azure database server.
Python
The language used for the short Function and worker. def defines a function, dictionaries hold named values, and with manages resource lifetimes such as connections.

Containers and Kubernetes

Docker image / container
An image packages files and startup configuration; a container is a running instance. A Dockerfile describes how to build an image.
Tag / digest
A tag is a convenient image name that can move. A digest identifies image content. Workshop tags are versioned from build inputs rather than called latest.
ACR
Azure Container Registry stores the built Products and ProductsChat images. Its pull permission belongs to the AKS kubelet identity.
AKS
Azure Kubernetes Service manages the Kubernetes control plane. The workshop creates a dedicated node pool; no pre-existing cluster is needed.
Pod / Deployment / Service
A Pod runs containers; a Deployment reconciles their desired number/version; a Service routes traffic to matching ready Pods.
Probe
A health check. Startup allows initialization; readiness controls traffic eligibility; liveness checks whether to restart a stuck process.
KEDA
A scaler that reads event-source metrics and changes Kubernetes replicas. It does not process queue messages or call the LLM.
HPA
Horizontal Pod Autoscaler: the Kubernetes controller KEDA supplies with metrics to scale between active replica counts.

Azure services and access

Blob container / blob
A logical grouping and an object in Azure Blob Storage. The private manuals container stores text blobs; it is unrelated to Docker containers.
Event Grid
Notification delivery that something happened, such as a blob being created. Its event identifies the blob; it does not carry the complete manual.
Service Bus
A broker for queued work and application communication. Requests and replies have separate queues with locks, acknowledgements, retries and dead-letter handling.
Azure Function / serverless
Code invoked by a configured trigger on platform-managed servers. Hosting dependencies, networking, identity and failure handling still exist.
Managed / workload identity
Managed identity gives an Azure resource an Entra identity. AKS workload identity exchanges a Kubernetes service-account token for that identity's Azure tokens through federation.
RBAC
Role-based access control: a principal, a role and a scope. Having a token proves identity; a suitable role grants the operation.
Key Vault / App Configuration
Key Vault stores actual secrets. App Configuration stores ordinary settings. Both are read at startup in this implementation; no live refresh is implied.
Private DNS / NAT gateway
Private DNS resolves PostgreSQL to its VNet address. NAT supplies explicit outbound internet connectivity for the AKS and Function subnets.

Delivery and consistency

Request ID / correlation ID
Persistent UUIDs identifying a question and its request/reply relationship. They appear in the database, messages, logs and polling URL.
Outbox
An outgoing message saved in the same database transaction as its request, then sent separately. It prevents a crash between committing a question and trying to send it from losing the work.
Idempotency
Handling repeated work without unwanted duplicate effects. Chunk uniqueness, immutable checksums, per-key locks, cached worker results and guarded reply updates support it here.
Message lock / acknowledgement
A temporary claim to process a message, followed by completion after success. Renewal handles long model calls; it does not promise exactly-once delivery.
Dead-letter queue / poison queue
Places to inspect work that cannot be processed after delivery failures. Event Grid, Service Bus and the Function Blob extension have separate failure stores.
