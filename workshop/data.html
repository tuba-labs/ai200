Chapter 05 of 10

Connect data, settings and identity

Connect PostgreSQL, storage, configuration and identities.

~30 minBash · repository root

Requires: stages 01–02 submitted and images pushed.

Wait, then configure

Bash · repository root
bash workshop/scripts/03-ready.sh
bash workshop/scripts/04-configure.sh

Canonical commands: commands.sh

03-ready.sh waits for ARM, a Ready node and the PostgreSQL VECTOR allowlist. 04-configure.sh assigns roles, federation, kubelet AcrPull, KEDA's separate identity and ordinary settings.

Bootstrap and federation

Applications start with APP_CONFIG_ENDPOINT and label workshop. App Configuration provides service settings and the vault URI; Key Vault supplies passwords. AKS requires the service-account annotation azure.workload.identity/client-id, Pod label azure.workload.identity/use: "true" and a federated credential matching issuer/subject/audience. See products.yaml and 04-configure.sh.

Inspect the Flyway migration

V1__products_and_messages.sql creates the schema when Products starts. Flyway records versions/checksums; reruns validate existing migrations.

Schema and upload consistency
  • Both document/question embeddings use the same deployment and vector(1536). Retrieval uses exact cosine distance <=>; no ANN index.
  • Chunk key: (manual_id, chunk_index). Chunks + ready state commit atomically.
  • Question + outbox commit together; replies/results persist by request ID.

The product row commits before blob upload. Failed uploads persist failure; abandoned waiting work times out. Manuals are immutable.

Database simplification

The workshop shares the workshopadmin database owner across migrations/apps, with its password in Key Vault. Production should separate runtime/migration roles. Private DNS/VNet access keeps PostgreSQL private; your laptop normally cannot connect directly.

Verification: node Ready, VECTOR allowlisted, settings/roles configured. Flyway runs in the next chapter.
Troubleshooting
  • Database DNS/connectivity: check the private zone's VNet link and delegated subnet; do not open an internet-wide firewall rule.
  • Vault/settings 403: check workload principal, role scope and propagation; CLI sign-in does not configure the Pod.
  • Extension failure: allowlist VECTOR; create SQL extension vector as the database owner.
  • KEDA authentication: inspect its own identity/federation, independently of the worker.
