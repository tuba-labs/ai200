Chapter 02 of 10

Check your starting point

Check tools, Azure permissions, regional capacity and model access.

~10 minBash · repository root

Required before the workshop

  • Account: an active Azure subscription with billing/credits. Plan roughly US$5–15 for a four-hour run and prompt cleanup; see cost assumptions.
  • Permissions: subscription Owner, or Contributor + Role Based Access Control Administrator. Organizational policy can still restrict deployments.
  • Capacity: regional services, eight free vCPUs for the selected VM family/region (node + upgrade surge), and chat/embedding model quota. The checker verifies these; actual model access is tested before AKS creation.
  • Computer: package-download access and a Linux-container Docker engine. Windows setup below targets x64 Windows 11 with virtualization/admin access; recommend 16 GB RAM and 30 GB free disk.

Local tools

Run workshop commands in Bash from the repository root. Windows tools installed outside WSL do not replace Linux tools.

ToolBaseline
Azure CLI / BicepCLI 2.91+ / Bicep 0.49.2
DockerEngine 24+ with BuildKit; running in Linux-container mode
Java / PythonJava 21; Python 3.12+ with venv/pip
kubectlInstaller uses 1.34.1; stay within one minor of AKS
UtilitiesBash 4+, Git, jq 1.6+, curl, OpenSSL 3, zip/unzip

No existing AKS cluster, local PostgreSQL, Helm or Functions host is needed.

Setup downloads

Windows setup (.ps1) · Ubuntu tools (.sh). Windows uses Docker Desktop + WSL2; native Linux can use Docker Engine. These scripts install local software only.

Windows / Ubuntu installation steps
  1. Review setup-windows.ps1. In Administrator PowerShell, open its download folder and run below. Add -WhatIf to preview. Install App Installer if WinGet is missing.
PowerShell · Windows Downloads folder
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup-windows.ps1

Canonical commands: setup-windows.ps1

  1. Restart if requested, then rerun. Open Ubuntu 24.04 and create its Linux user. wsl --list --verbose should show version 2.
  2. Start Docker Desktop; choose WSL2/Linux containers and enable Settings → Resources → WSL Integration → Ubuntu-24.04. Review Docker's license requirements; WinGet accepts package/source agreements.
  3. Copy/extract the repository into Ubuntu, e.g. ~/ai200. In that repository root, run:
Bash · repository root
bash workshop/scripts/setup-ubuntu.sh

Canonical commands: commands.sh

The Ubuntu script installs the listed tools and workshop/.tools/venv. No second Docker daemon is installed. See setup-ubuntu.sh or the official installation links for other systems.

Already set up? Check local tools without Azure sign-in:

Bash · repository root
python3 workshop/tools/preflight.py --local-only

Canonical commands: commands.sh

Sign in and check Azure

Run az login, deliberately select your development subscription with az account set --subscription SUBSCRIPTION_ID, then confirm az account show.

Bash · repository root
python3 workshop/tools/bootstrap.py
bash workshop/scripts/00-check.sh

Canonical commands: commands.sh

Bootstrap saves non-secret config in workshop/.state/config.json: Sweden Central, prefix raglab, selected subscription and your public IPv4 /32. Review it. Shared subscription? Give each participant a different --prefix. Other overrides: bootstrap.py.

Checker failures and provider registration

If providers are unregistered, register them and rerun the checks:

Bash · repository root
bash workshop/scripts/00-check.sh --register

Canonical commands: commands.sh

  • Missing quota/model offers: register providers first; empty API results do not prove capacity. Check Subscription → Usage + quotas or change region.
  • Permission denied: obtain the subscription roles listed above; check deny policies.
  • Docker unavailable: start Desktop and enable Ubuntu integration.
  • Java mismatch: select Java 21 through JAVA_HOME/PATH in Bash.

Keep the same prefix/subscription after provisioning; change a colliding name before creation. If your VPN/public IP changes, update the exact allowed /32.
