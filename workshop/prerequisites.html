Check your starting point

Use one Bash environment and catch permissions, quota and model-access blockers early.

~10 minutes · estimateBash · repository rootCore path

You will learn: how to make Azure identity, regional availability and quota explicit before starting expensive work.

Starting requirements: a suitable Azure subscription and permission to create resources and role assignments. Software installation is preparation time, not part of the four-hour estimate.

Shell and directory: Bash, at the repository root. On Windows use Ubuntu 24.04 in WSL2, with Docker Desktop's WSL integration enabled for that distribution. Keep this environment for every Azure command.

Have these ready before the workshop

  • Azure account and subscription: a Microsoft or work/school account that can sign in to an active Azure subscription. An account alone is not a subscription. Confirm billing or credits cover the selected services, accept the estimated costs, and choose a development subscription you can clean up afterward. A free/trial subscription does not guarantee the required model or VM quota.
  • Azure permissions: Owner, or Contributor plus Role Based Access Control Administrator, at subscription scope. Arrange this with the subscription owner before starting. You need to create resources, register providers and assign identities; tenant administration alone does not grant these permissions.
  • Capacity and model access: the chosen region must support AKS, PostgreSQL, Functions Flex and the selected chat/embedding models. The checker below verifies offers and quotas; the next chapter makes real model calls before starting AKS. Resolve organizational restrictions and quota requests in advance.
  • A development computer: a browser, the supplied repository files and a terminal. For the supplied Windows installer use supported x64 Windows 11 with hardware virtualization enabled and local administrator access. We recommend 16 GB RAM and 30 GB free disk space for WSL, images and build caches. Follow Docker's current system requirements if using another supported Windows configuration.
  • Network access: allow software/package downloads, Azure sign-in and Azure service endpoints. Know whether a corporate proxy, VPN or device policy blocks Docker/WSL, package installation or cloud resource creation.
  • Local software: the tools listed below, installed in the same Bash environment, and a running Linux-container Docker engine. No pre-existing AKS cluster, database or other Azure resources are required.

Windows: download the setup script

Yes, the documented Windows path uses Docker Desktop. It provides the local Linux-container engine for building, running, tagging and pushing images. Start it during the workshop. On native Linux an existing Docker Engine 24+ with BuildKit is sufficient. Merely reading or serving this documentation does not require Docker or Azure access.

Download Windows setup (.ps1) · Download Ubuntu tool setup (.sh). Review scripts/setup-windows.ps1 and scripts/setup-ubuntu.sh before running them. They install local software only and do not sign in, register Azure providers or create cloud resources. Review Docker Desktop's license terms for your organization. The WinGet invocation accepts package/source agreements; application first-run setup remains interactive.

  1. Open PowerShell as Administrator, change to the folder containing the downloaded setup-windows.ps1 (normally Downloads), and run the command below. Add -WhatIf to preview the actions. The process-only execution-policy flag permits this reviewed script without changing the machine's saved execution policy. If WinGet is missing, install/update Microsoft's App Installer first.
PowerShell · Windows Downloads folder
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup-windows.ps1

Canonical commands: scripts/setup-windows.ps1

  1. The script uses WinGet to install Docker Desktop and wsl --install --distribution Ubuntu-24.04 --no-launch to enable/install WSL and Ubuntu. Existing installations are preserved. Restart if Windows requests it, then rerun the script to finish. Allow download/restart time before the four-hour core path.
  2. Open Ubuntu 24.04 from Start, or run wsl -d Ubuntu-24.04. Create a Linux username/password on first launch. In PowerShell, wsl --list --verbose must show version 2 for this distribution.
  3. Start Docker Desktop. Select the WSL2 engine and Linux containers; under Settings → Resources → WSL Integration, enable Ubuntu-24.04 and apply the change. A local Kubernetes cluster in Docker Desktop is unnecessary.
  4. In Ubuntu Bash, copy/extract the supplied repository into a Linux folder such as ~/ai200, then open that repository root. You should see index.html and workshop/. A Windows checkout can also be reached through /mnt/c/, although a Linux filesystem copy avoids slower bind mounts and line-ending issues. Run the supplied Ubuntu setup from the repository, so it can also install the workshop's Python requirements:
Bash · repository root
bash workshop/scripts/setup-ubuntu.sh

Canonical commands: commands.sh

The Ubuntu script uses apt for Java 21, Python 3.12, Bash, Git, jq, curl, OpenSSL, archive tools and Azure CLI from Microsoft's signed repository. It installs Bicep 0.49.2 and checksum-verifies kubectl 1.34.1. It creates workshop/.tools/venv for the pinned client dependencies. It does not install a second Docker daemon inside WSL. Windows Azure CLI, Python and Java installations do not substitute for these Linux tools.

Have the tools already? Skip installation and run this local check, which requires neither Azure sign-in nor bootstrap state:

Bash · repository root
python3 workshop/tools/preflight.py --local-only

Canonical commands: commands.sh

Create the small bootstrap configuration

Bash · repository root
python3 workshop/tools/bootstrap.py
bash workshop/scripts/00-check.sh

Canonical commands: commands.sh

The bootstrap tool reads the selected subscription, chooses swedencentral, and creates names from the prefix raglab plus a subscription-derived suffix. It detects the calling network's public IPv4 and restricts the Products service to that /32. Review the printed non-secret configuration.

Use --subscription, --location, --prefix or --allowed-cidr on tools/bootstrap.py when needed, or provide a reviewed copy of config.example.json with --config. The prefix must contain 3–8 lowercase letters/digits and start with a letter; generated Storage, ACR and Key Vault names respect their length/character constraints. Globally unique names may still be reserved or soft-deleted: change the prefix before creating resources if Azure reports a collision.

workshop/.state/config.json contains non-secret resume state and is ignored by Git. Scripts reuse it rather than silently switching subscriptions. Do not edit its subscription or prefix after creating resources. The website never reads it and never asks you to put credentials in browser storage or URLs.

If several participants share one Azure subscription, give each person a distinct prefix before provisioning. The default prefix intentionally reuses the same workshop resources in that subscription; it is not per-browser isolation.

Read and fix the checker results

tools/preflight.py checks tool versions, Docker, sign-in, subscription state, provider registration, creation/role-assignment permissions, regional service offers, a compatible VM SKU, CPU quota including upgrade surge, and model offers/quota. It stops on unknown critical quota results; a missing API response is not evidence of capacity.

Use Owner, or Contributor plus Role Based Access Control Administrator, at subscription scope for this workshop. A resource-scoped Contributor alone cannot register providers or assign the required identities. Organizational policy and deny assignments can still block operations even when these roles are present.

If providers are unregistered, the following explicitly registers them, waits with a bounded readiness check, and reruns the checks. Unregistered Compute or model providers can also make quota/offer queries return empty results, so register first rather than assuming that empty results prove no quota:

Bash · repository root
bash workshop/scripts/00-check.sh --register

Canonical commands: commands.sh

Expensive blockers: one D4ds_v5 node needs four vCPUs, and the check reserves another four for an upgrade surge. Confirm PostgreSQL Burstable capacity and Flex regional quota in the portal if your subscription restricts them. Model listings are not proof of inference access; chapter 3 creates only the model resource first and makes actual calls before AKS starts.

Expected results and common failures

Verification: the checker should end with “All read-only gates passed.” This is expected output, not a claim about your subscription. At this point no paid resources should have been created.
  • Docker daemon unavailable: start Docker Desktop, enable this WSL distribution, reopen Ubuntu and retry docker info.
  • Java version is not 21: install OpenJDK 21 and set JAVA_HOME and PATH in this Bash session. A Windows JDK outside WSL does not install a Linux JDK.
  • Quota/API response missing: use Azure portal → Subscription → Usage + quotas. Ask the owner to increase the chosen VM family and model quota, or choose a region offering all required services. Do not bypass the check by reducing it to zero.
  • Role assignment write denied: ask the subscription owner for the role stated above. Tenant admin consent is different from Azure resource RBAC.
  • Your public IP changes: stop and update the allowed /32 before applying the service. A VPN can change which address Azure sees.

Continue when: all read-only checks pass, the subscription is correct and the cost explanation in the next chapter is acceptable.
