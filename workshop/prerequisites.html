Check your starting point

Use one Bash environment and catch permissions, quota and model-access blockers early.

~10 minutes · estimateBash · repository rootCore path

You will learn: how to make Azure identity, regional availability and quota explicit before starting expensive work.

Starting requirements: a suitable Azure subscription and permission to create resources and role assignments. Software installation is preparation time, not part of the four-hour estimate.

Shell and directory: Bash, at the repository root. On Windows use Ubuntu 24.04 in WSL2, with Docker Desktop's WSL integration enabled for that distribution. Keep this environment for every Azure command.

Prepare one environment

Install WSL2 and enable Docker Desktop integration if you use Windows. Run the commands inside Ubuntu, not a PowerShell tab. macOS and Linux Bash also work if the listed tools are available. Images target linux/amd64, matching the supplied AKS node.

Use Microsoft's Azure CLI installation instructions and az bicep install. Use az aks install-cli if you need kubectl. Helm, a local Functions host and a local PostgreSQL installation are not required for the core path: Azure CLI handles Function package deployment; AKS supplies KEDA.

Sign in with az login, select the intended subscription using az account set --subscription ..., then inspect az account show. This is the one subscription choice to make deliberately. Do not continue if the selected subscription belongs to a customer or production environment.

Create the small bootstrap configuration

Bash · repository root
python3 workshop/tools/bootstrap.py
bash workshop/scripts/00-check.sh

Canonical commands: commands.sh

The bootstrap tool reads the selected subscription, chooses swedencentral, and creates names from the prefix raglab plus a subscription-derived suffix. It detects the calling network's public IPv4 and restricts the Products service to that /32. Review the printed non-secret configuration.

Use --subscription, --location, --prefix or --allowed-cidr on tools/bootstrap.py when needed, or provide a reviewed copy of config.example.json with --config. The prefix must contain 3–8 lowercase letters/digits and start with a letter; generated Storage, ACR and Key Vault names respect their length/character constraints. Globally unique names may still be reserved or soft-deleted: change the prefix before creating resources if Azure reports a collision.

workshop/.state/config.json contains non-secret resume state and is ignored by Git. Scripts reuse it rather than silently switching subscriptions. Do not edit its subscription or prefix after creating resources. The website never reads it and never asks you to put credentials in browser storage or URLs.

If several participants share one Azure subscription, give each person a distinct prefix before provisioning. The default prefix intentionally reuses the same workshop resources in that subscription; it is not per-browser isolation.

Read and fix the checker results

tools/preflight.py checks tool versions, Docker, sign-in, subscription state, provider registration, creation/role-assignment permissions, regional service offers, a compatible VM SKU, CPU quota including upgrade surge, and model offers/quota. It stops on unknown critical quota results; a missing API response is not evidence of capacity.

Use Owner, or Contributor plus Role Based Access Control Administrator, at subscription scope for this workshop. A resource-scoped Contributor alone cannot register providers or assign the required identities. Organizational policy and deny assignments can still block operations even when these roles are present.

If providers are unregistered, the following explicitly registers them, waits with a bounded readiness check, and reruns the checks. Unregistered Compute or model providers can also make quota/offer queries return empty results, so register first rather than assuming that empty results prove no quota:

Bash · repository root
bash workshop/scripts/00-check.sh --register

Canonical commands: commands.sh

Expensive blockers: one D4ds_v5 node needs four vCPUs, and the check reserves another four for an upgrade surge. Confirm PostgreSQL Burstable capacity and Flex regional quota in the portal if your subscription restricts them. Model listings are not proof of inference access; chapter 3 creates only the model resource first and makes actual calls before AKS starts.

Prepare the small verification environment

Bash · repository root
python3 -m venv workshop/.tools/venv
# shellcheck source=/dev/null
source workshop/.tools/venv/bin/activate
python -m pip install -r workshop/requirements-test.txt

Canonical commands: commands.sh

This virtual environment is for smoke/load tools and local tests. It does not change the Python installed by Azure Functions. To resume in another terminal, run source workshop/.tools/venv/bin/activate. Container builds install their own pinned requirements.

Expected results and common failures

Verification: the checker should end with “All read-only gates passed.” This is expected output, not a claim about your subscription. At this point no paid resources should have been created.
  • Docker daemon unavailable: start Docker Desktop, enable this WSL distribution, reopen Ubuntu and retry docker info.
  • Java version is not 21: install OpenJDK 21 and set JAVA_HOME and PATH in this Bash session. A Windows JDK outside WSL does not install a Linux JDK.
  • Quota/API response missing: use Azure portal → Subscription → Usage + quotas. Ask the owner to increase the chosen VM family and model quota, or choose a region offering all required services. Do not bypass the check by reducing it to zero.
  • Role assignment write denied: ask the subscription owner for the role stated above. Tenant admin consent is different from Azure resource RBAC.
  • Your public IP changes: stop and update the allowed /32 before applying the service. A VPN can change which address Azure sees.

Continue when: all read-only checks pass, the subscription is correct and the cost explanation in the next chapter is acceptable.

A reading checklist, not proof of a successful Azure deployment.
