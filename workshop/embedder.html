Turn a manual into vectors

Deploy a Python Function whose Event Grid-backed Blob trigger chunks and indexes an immutable manual safely.

~30 minutes · estimateBash · repository rootCore path

You will learn: Python's small functions, the difference between an event and file contents, chunking, embeddings and retry-safe persistence.

Starting requirements: Products is deployed, Flyway ran, and the Azure model probe passed. Do not upload the first manual until this chapter's subscription is ready.

Shell and directory: Bash, repository root. Activate workshop/.tools/venv for the optional sample/replay tools.

Understand the trigger before publishing

Read apps/products-embedder/function_app.py. The decorator declares a blobTrigger, connection prefix ManualStorage, path matching manuals/products/{productId}/{manualId}.txt, and source='EventGrid'. Azure Functions' Blob extension handles the notification and reads the file; the Python function receives an InputStream. It extracts stable IDs from the path and passes bytes to the small indexing helper.

Our explicit Event Grid subscription filters BlobCreated notifications to this container/path and .txt suffix. Its destination is the Function's Blob-extension webhook, not an ordinary HTTP trigger or a Service Bus queue. The Blob-extension system key protects that webhook; the script handles it without printing it or saving it in the website.

Flex Consumption supports Python 3.12, VNet integration and the Event Grid source for Blob triggers. It uses a blob deployment container rather than Azure Files. The template supplies the deployment identity, identity-based AzureWebJobsStorage, Blob/Queue connection endpoints, the delegated subnet and telemetry settings. Host storage is infrastructure for the Functions runtime, distinct from the manual that your code indexes.

Publish code and connect notifications

Bash · repository root
bash workshop/scripts/07-embedder.sh

Canonical commands: commands.sh

The packaging helper gathers the real Python sources and canonical requirements into a ZIP. Azure CLI requests a remote Linux build and package deployment; Windows-built native packages are not uploaded. The stage then creates a Storage system topic, grants its dead-letter identity access to the private dead-letter container, waits for the blobs_extension host key, and registers the filtered webhook.

“Serverless” still means code runs on servers. The platform manages those servers and invocation scaling. It does not remove the need for host storage, a deployment package, identity roles, networking or timeout handling.

Upload a supplied manual

Return to Products → Upload product. Use product name Aurora Trail Lamp and download/select aurora-trail-lamp.txt. Upload it once. The row should move through waiting, processing and ready; a quick run may make an intermediate state too brief to notice. Upload completion and embedding completion are separate events.

Then upload Cedar Desk Fan using its manual, and Harbor Travel Kettle using its manual. Distinctive specifications make later retrieval objectively inspectable. The manuals are short fictional data, not manufacturer safety guidance.

Read the chunking and indexing code

apps/shared/rag_core/chunks.py uses readable loops, string slices and paragraph/sentence/whitespace boundaries. It caps chunks at the configured character count and includes a little overlap so a boundary is less likely to separate a specification from its product name. Characters are a simple workshop approximation, not the model's tokenizer.

apps/shared/rag_core/models.py calls the Azure-hosted embedding deployment with the identity token and explicitly requests 1536 dimensions. Both this Function and the chat worker use that same deployment and dimension. The embedding response is a list of numbers, not a text answer.

apps/shared/rag_core/embedding.py takes a per-manual PostgreSQL advisory lock. It verifies the record and checksum, commits the visible processing state, obtains embeddings, and writes all chunks and the ready state in one transaction. The uniqueness rule is (manual_id, chunk_index). A ready manual returns without calling the model again. Failed attempts persist a safe error and raise so the Functions extension can retry; repeated failures eventually reach its poison queue.

This protects against repeated notifications and crashes around persistence. It is not a claim of exactly-once event delivery. Immutable blob paths keep event versioning understandable; replacing a blob under the same path violates the core path's checksum rule.

Inspect counts and dimensions, not huge vectors

Bash · repository root
bash workshop/scripts/inspect-data.sh

Canonical commands: commands.sh

The script runs a bounded Job inside the VNet, using the worker's identity and configuration. It prints each product/manual ID, status, number of chunks, and minimum/maximum vector dimensions. Expect nonzero chunks and dimensions 1536 for every ready manual. The actual chunk count depends on text and the configured size. No 1536-number arrays or passwords are dumped.

Verification: all three manuals are ready; their chunk counts are positive; minimum and maximum vector dimensions are both 1536. Use these actual observations before continuing to chat.

Two small, observable exercises

  1. Change a manual: save a copy of Aurora's file, change 420 lumens to 510 lumens, and call it revision B in its text. Upload it as a new product named “Aurora Trail Lamp Rev B”. Keep both products. In the next chapter, selecting each product should retrieve its own specification.
  2. Observe duplicate handling: while the verification virtual environment is active, run python workshop/tools/replay_event.py to replay a ready manual's BlobCreated event twice. Then rerun the data inspection. Counts should be unchanged. The Blob extension can suppress a duplicate through its receipt; if application code runs, its ready/checksum guard independently prevents extra rows. Local integration tests exercise that code path directly.

Common failures and fixes

  • Manual stays waiting: confirm the event subscription exists and is Succeeded, the source container/path matches, and IndexManual appears in the Function list. Upload a new product if the original upload preceded subscription creation.
  • No host key or Function discovery: inspect remote build logs, the 4.x extension bundle and the managed identity's Storage Blob Data Owner, Queue Data Contributor and Account Contributor roles. Those host permissions are broader than merely reading a manual.
  • Manual fails during indexing: inspect Function traces by manual ID in Application Insights. Check database DNS/connectivity, model RBAC/quota and vector dimensions. Inspect webjobs-blobtrigger-poison in the host storage queues after repeated failures.
  • Event delivery fails permanently: inspect the private event-deadletters blob container and the system topic identity's role. Event Grid dead letters and the Function Blob-trigger poison queue are different failure locations.

Continue when: at least the original three supplied manuals are ready and have 1536-dimensional chunks. Now the worker can retrieve real evidence.

A reading checklist, not proof of a successful Azure deployment.
