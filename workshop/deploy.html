Chapter 06 of 9

Deploy Products to AKS

Deploy Products; inspect probes, logs and a rollout.

~20 minBash · repository root

Requires: stages 03–05 pass; images are in ACR.

Deployment, Service and probe basics
  • products.yaml: Deployment keeps one Java Pod running; service account + Pod labels enable identity. Startup permits initialization; readiness checks the database; liveness checks the process.
  • service.yaml: LoadBalancer Service selects ready Products Pods and forwards 443 → 8443. Access is restricted to your public IPv4 /32.

Deploy and sign in

Bash · repository root
bash workshop/scripts/06-products.sh

Canonical commands: commands.sh

The stage creates the Service, waits for an IP, installs a TLS Secret and deploys Products. Open the printed URL; username participant, password from bash workshop/scripts/credentials.sh in your terminal.

TLS: the two-day certificate is self-signed. Compare the printed SHA-256 fingerprint before accepting the browser warning. CLI tools trust workshop/.state/tls.crt.

Inspect and restart

Bash · repository root
export KUBECONFIG="$PWD/workshop/.state/kubeconfig"
kubectl get deployment,pods,service -n products
kubectl logs deployment/products -n products --tail=50
kubectl describe pod -n products -l app=products
kubectl rollout restart deployment/products -n products
kubectl rollout status deployment/products -n products --timeout=300s

Canonical commands: commands.sh

Find one ready Pod, the load-balancer IP, Flyway startup/validation and probe settings. The restart replaces the Pod and reuses the database schema.

Verification: sign in and open both upload/chat views; the restarted deployment becomes Ready. Wait until the next chapter's Function subscription is ready before uploading. Earlier BlobCreated events are not replayed automatically.
Troubleshooting
  • ImagePullBackOff: describe the Pod; verify the pushed tag and kubelet AcrPull role.
  • CrashLoopBackOff: inspect kubectl logs -n products deployment/products --previous; check settings, vault and private DB access.
  • Endpoint blocked: check VPN/public IP against allowedCidr; update the exact /32 and rerun stage 06.
  • Expired certificate: rerun stage 06, restart Products and check the new fingerprint.
  • Write API 403: use the UI or obtain CSRF/session state from /api/csrf, as the supplied clients do.
