Chapter 10 of 10

Verify, diagnose and clean up

Smoke-test the deployment, diagnose failures and remove resources.

~15 minBash · repository root

Requires: all components ready, manuals indexed, KEDA Ready and demo delay disabled.

Run the deployment smoke test

Bash · repository root
# shellcheck source=/dev/null
source workshop/.tools/venv/bin/activate
python workshop/tools/smoke.py

Canonical commands: commands.sh

Checks dependency readiness, uploads Aurora, waits for indexing, submits a temperature question and validates correlation + source evidence. Timeouts: seven minutes for indexing, eight for the reply. Results: workshop/.state/smoke-result.json.

Verification: smoke passes with a non-empty answer and the matching temperature passage/product/manual IDs. Exact model wording is not asserted. Maintainer validation records which checks actually ran.

If something fails

Bash · repository root
bash workshop/scripts/diagnostics.sh

Canonical commands: commands.sh

Troubleshooting by boundary
SymptomCheck / fix
Upload failedProducts logs and Blob role/endpoint; retry as a new product after fixing
Manual waitingEvent filter, webhook and Function discovery; pre-subscription uploads need replay/new product
Indexing failedManual-ID traces, model identity/quota/dimensions and private DB access
Question queuedOutbox, queue, worker and ScaledObject; check sender/scaler/receiver roles separately
Question processing/failedWorker request-ID logs, model throttling, lock renewal and deadline
Wrong evidenceProduct filter, stored chunks, retrieval count and prompt

Function logs: function-logs.kql in Application Insights. Failure stores are separate: Event Grid's event-deadletters blobs, Function host's webjobs-blobtrigger-poison, and Service Bus $DeadLetterQueue. Do not dump webhook destination URLs; they contain a system key.

Clean up

Bash · repository root
bash workshop/scripts/cleanup.sh

Canonical commands: commands.sh

The tool verifies the tagged workshop group, lists resources and requires DELETE plus its full name. After submission, run the printed az group exists check until false; confirm AKS's managed node group is also gone. Deletion may be blocked by locks/policy.

Soft delete and local cleanup

Key Vault has seven-day soft-delete retention; App Configuration one day. No purge is performed, so names may remain reserved. Provider registrations remain. Remove local workshop/.state only after Azure cleanup is confirmed.
