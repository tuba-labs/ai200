Implementation decisions

The core deliberately favors explicit code: Java 21, supported Spring Boot, Maven Wrapper, JdbcClient/SQL, Thymeleaf and Flyway; Python 3.12, direct Azure SDK clients and small HTTP model calls; PostgreSQL 17 and an exact pgvector cosine scan. Application folders can later become separate repositories. The tiny shared Python package can be published as a versioned internal wheel or copied into each Python repository; the current Function ZIP and worker image include the same canonical package.

PostgreSQL is private to the VNet, with a delegated subnet and private DNS. AKS and Functions use explicit NAT egress for public, identity-protected Azure endpoints. Storage containers are private and shared-key access is disabled. This core avoids private endpoints for every service and avoids a multi-day network/security course.

One database owner is used by migrations and applications, and TLS sslmode=require encrypts PostgreSQL traffic inside the private network. Production should separate runtime/migration roles and use full certificate/hostname verification appropriate to its trust store. The Products endpoint has self-signed HTTPS, a source-IP restriction and a random password. It is not public anonymous HTTP, nor a production SSO implementation.

Application settings/secrets are read only on startup. Workers are serial with prefetch zero. Messaging is at-least-once with explicit idempotency. Model calls have finite connect/read timeouts; request deadlines and failure states persist independently of the browser.

Cost drivers and cleanup

The four-hour US$5–15 planning allowance is intentionally approximate. It assumes one small node, a Burstable database, a few manuals, at most a handful of bounded eight-question demos, and prompt deletion. No bill has been measured for this implementation. Regional capacity, pricing agreements, minimum billing units and model token usage change the result.

  • Persistent until deletion: AKS node/disks, database compute/storage, NAT/public IPs, ACR, Service Bus and App Configuration. Scaling the chat worker to zero does not remove these costs.
  • Usage-based: model tokens, Function execution, storage operations/data transfer and log ingestion. Restrict repeated load runs; failed/retried model calls can also cost tokens.
  • After cleanup: confirm ARM deletion and AKS's node-group removal. Soft-deleted Key Vault/App Configuration names remain subject to their recovery/retention behavior.

Use Azure Pricing Calculator, AKS pricing, PostgreSQL pricing and Azure model pricing before your own run. Budget alerts notify; they are not a hard spending cap.
