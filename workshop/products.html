Chapter 04 of 9

Read, build and run Products

Build, tag, push and run the supplied Java/Python images.

~35 minBash · repository root

Requires: stage 02 submitted, ACR created and Docker running. Azure can still be provisioning.

Application source walkthrough
  • ProductsController.java: validate UTF-8 .txt, commit product/manual IDs, upload the private blob.
  • Store.java + MessagePump.java: explicit SQL, persistent chat/outbox and reply handling.
  • Thymeleaf templates + app.js: server-rendered forms and browser polling.
Dockerfile and container basics

An image packages the application; a container runs it. The build stage uses Maven/Java 21; the runtime copies only the JAR and runs unprivileged. EXPOSE documents a port; docker run -p publishes it.

Dockerfile is maintained in the Products repository.

Build, tag and push

Bash · repository root
bash workshop/scripts/05-images.sh

Canonical commands: commands.sh

05-images.sh builds both images for linux/amd64, logs into ACR, assigns content-derived w1-… tags with -t, and pushes. Products uses its app folder as build context; the worker uses the repository root for shared Python code. State/secrets are excluded.

Run locally

Bash · repository root
tag=$(python3 -c 'import json; print(json.load(open("workshop/.state/images.json"))["tag"])')
registry=$(python3 -c 'import json; print(json.load(open("workshop/.state/config.json"))["stem"]+"acr.azurecr.io")')
docker run --rm --name products-inspect -p 127.0.0.1:8080:8080 \
  "$registry/products:$tag" --spring.profiles.active=inspect

Canonical commands: commands.sh

In another Bash terminal:

Bash · repository root
curl --fail http://127.0.0.1:8080/
curl --fail http://127.0.0.1:8080/actuator/health/liveness
docker ps
docker logs products-inspect --tail=30

Canonical commands: commands.sh

Expect Inspect profile and health UP. This profile has no upload/chat or Azure connections. Stop the container with Ctrl+C.

Exercise: tag the same image / build Java locally

Using the run block's variables, execute docker tag "$registry/products:$tag" products-local:$tag, then docker image inspect "products-local:$tag". Both references identify the same image; a tag can move, a digest identifies content.

For a local Java build: in the sibling ai200-workshop1-products checkout, run bash mvnw test with Java 21. Integration tests need the database fixture.

Verification: both pushes return digests and localhost health is UP. Continue to data/identity setup.
Troubleshooting
  • Push denied: check subscription/push rights and rerun the stage's ACR login.
  • Port busy: map 127.0.0.1:8081:8080 and use 8081 locally.
  • Download failure: check Docker's network/proxy and rerun; completed layers are cached.
  • Exec format error: use the supplied linux/amd64 platform.
