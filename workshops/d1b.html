Which KEDA settings select a Storage queue and its scaling target?

For an azure-queue rule, accountName and queueName identify the queue; queueLength sets the target backlog per replica. For example, accountName=mystorage queueName=jobs queueLength=5 selects jobs and targets about five messages per replica. The rule also needs queue access.

What are the Container Apps min/max replica settings used for?

minReplicas sets the scaling floor; maxReplicas sets the ceiling. For example, values of 1 and 5 let the scaler request between one and five replicas. A minimum of 0 permits the app to stop all replicas while idle.

What is the default polling interval for Container Apps event-driven scaling?

30 seconds for custom KEDA event-source rules by default. This is how often the scaler checks the source for work, such as messages waiting in a queue.

When does the default 300-second Container Apps cooldown apply?

When an inactive app scales from its last replica to zero. The cooldown waits after the source stops reporting activity before removing that final replica. It is not a 300-second delay on every decrease between nonzero replica counts.

How is the target replica count estimated from a queue-length metric?

Divide the queue length by the target messages per replica and round up. For 12 messages and a target of 5, 12 ÷ 5 rounds up to 3 replicas. The configured minimum and maximum then bound that target.

Praktisk oppgave8 tilknyttede kort

Rull ut, finn en feil tag og rull tilbake

  1. Opprett namespace ai200-v2. Rediger bare den nye kopien av deployment.yaml: sett image til AI200_IMAGE. Apply er avgrenset til dette namespace-et.
  2. Vent på rollout, kall /health med port-forward, og noter podnavn og image-digest. Skaler til to podder.
  3. Sett en ugyldig image-tag, bruk describe/events og finn ImagePullBackOff. Kjør rollout undo og bekreft at /health virker igjen. Bruk logs --previous bare når en tidligere containerinstans faktisk finnes.

kubectl create namespace ai200-v2
# Bruk manifestet med ditt tilgjengelige image.
kubectl apply -n ai200-v2 -f workshops/labs/containers/deployment.yaml
# Vent på at utrullingen blir klar.
kubectl rollout status -n ai200-v2 deployment/workshop-api
# Se hendelser og containerstatus.
kubectl describe pods -n ai200-v2
# Gjør helseruten tilgjengelig lokalt; la denne terminalen stå åpen.
kubectl port-forward -n ai200-v2 deployment/workshop-api 8088:8080

# Bruk Kubernetes-API-et for Deployment-ressurser.
apiVersion: apps/v1
# En Deployment vedlikeholder ønsket antall pod-replikaer.
kind: Deployment
# Metadata identifiserer selve Deployment-ressursen.
metadata:
  # Bruk dette navnet i kubectl rollout, logs og scale.
  name: workshop-api
# Beskriv ønsket tilstand for Deployment-en.
spec:
  # Start med én pod; senere skalerer du til to.
  replicas: 1
  # Velg hvilke pods Deployment-en skal styre.
  selector:
    # Match podenes labels nøyaktig.
    matchLabels:
      # Selectoren må passe med labelen i pod-malen under.
      app: workshop-api
  # Denne malen brukes til å opprette hver pod.
  template:
    # Dette er metadata for podene, ikke for Deployment-en.
    metadata:
      # Sett labels som Deployment og Service kan velge etter.
      labels:
        # Bruk samme app-label som selectoren over.
        app: workshop-api
    # Beskriv innholdet i hver pod.
    spec:
      # Denne poden inneholder én applikasjonscontainer.
      containers:
        # Gi containeren et navn i podens logger og status.
        - name: api
          # Bytt til hele ACR-adressen og taggen du skal teste.
          image: ai200-api:v2
          # Hent imaget hvis noden ikke allerede har denne taggen lokalt.
          imagePullPolicy: IfNotPresent
          # Dokumenter portene containeren lytter på.
          ports:
            # Appen lytter på port 8080 inne i containeren.
            - containerPort: 8080
          # Angi ressursbehov og øvre grenser for containeren.
          resources:
            # Scheduler bruker disse behovene ved plassering på en node.
            requests:
              # Be om 0,1 CPU-kjerne.
              cpu: 100m
              # Be om 64 MiB minne.
              memory: 64Mi
            # Sett øvre grenser for containerens ressursbruk.
            limits:
              # Begrens CPU-bruken til 0,25 kjerne.
              cpu: 250m
              # Minnegrensen er 128 MiB; overskridelse kan avslutte containeren.
              memory: 128Mi
          # Avgjør om poden er klar til å motta tjenestens trafikk.
          readinessProbe:
            # Bruk en HTTP-forespørsel som readiness-kontroll.
            httpGet:
              # Denne stien skal gi et vellykket HTTP-svar.
              path: /health
              # Send kontrollen til appens containerport.
              port: 8080
            # Vent to sekunder før første readiness-kontroll.
            initialDelaySeconds: 2
            # Gjenta kontrollen hvert femte sekund.
            periodSeconds: 5

What does a Kubernetes Deployment manifest describe?

The desired application setup: replica count, pod-template labels, container image and settings. Its selector must match the pod-template labels so the Deployment knows which pods it manages. Kubernetes uses this desired state to create and update the actual workload.

m-15-1-1 · Åpne dette flashcardet

Which kubectl command creates or updates resources from a manifest file?

Run: kubectl apply -f deployment.yaml This creates missing resources or updates existing ones to match the manifest’s declared configuration. The controllers then carry out the required changes.

m-15-2-1 · Åpne dette flashcardet

What is the sequence for a rolling image update in Kubernetes?

Change the container image reference in the Deployment manifest, then run: kubectl apply -f deployment.yaml kubectl rollout status deployment/myapp Replace myapp with the Deployment name. With RollingUpdate, pods are replaced gradually. Readiness checks, available capacity and the update strategy determine whether requests continue to succeed throughout the rollout.

m-15-3-1 · Åpne dette flashcardet

Which command rolls a Kubernetes Deployment back?

Run kubectl rollout undo deployment/myapp, replacing myapp with the Deployment name. It restores the previous retained pod-template revision. To choose a particular retained revision, add --to-revision=<number>. Monitor the result with kubectl rollout status deployment/myapp.

m-15-4-1 · Åpne dette flashcardet

Which command changes a Deployment's replica count manually?

Run kubectl scale deployment/myapp --replicas=5. Replace myapp with the Deployment name. This changes the desired pod count to five; the controller then tries to create or remove pods to match it. An active autoscaler may subsequently change that count again.

m-16-6-1 · Åpne dette flashcardet

Which two kubectl commands are a useful starting point for investigating an unhealthy pod?

Start with kubectl describe pod <pod-name> for status and events, then kubectl logs <pod-name> for application output. Determine whether the failure concerns scheduling, startup, probes or the application before changing configuration.

m-17-1-1 · Åpne dette flashcardet

What does ImagePullBackOff indicate?

Kubernetes failed to download the container image and is waiting before retrying. Inspect pod events for the cause, such as a wrong tag, missing registry permission or a network/DNS error.

m-17-3-1 · Åpne dette flashcardet

Which kubectl commands show current pod or node CPU and memory usage?

Use kubectl top pods, or kubectl top nodes for node-level usage. These commands need a working resource-metrics provider, normally metrics-server. They show current CPU and memory measurements, helping distinguish measured usage from the requests/limits in the manifest.

Which Kubernetes Service type is the default?

ClusterIP. It gives the Service an address reachable inside the cluster, so clients can use that stable address to reach the selected pods.

m-09-1-1 · Åpne dette flashcardet

What happens when a Kubernetes readiness probe fails?

The pod is marked not ready and stops receiving normal Service traffic. The container keeps running; readiness failure alone does not restart it. This lets an application temporarily withdraw from traffic while it initializes or recovers.

m-11-2-1 · Åpne dette flashcardet

What should you check when running pods receive no traffic through their Kubernetes Service?

Check that the Service selector matches the pod labels, the pods are Ready and the Service has matching endpoints. Then compare the Service’s targetPort with the port the app actually listens on. These checks distinguish “the process is running” from “the Service can route to it.”

What is the purpose of a Kubernetes startup probe?

It gives a slow-starting container time to initialize. While the startup probe has not succeeded, liveness and readiness probes are held back. Once it succeeds, those probes take over. Repeated startup failures beyond its threshold can still cause the container to restart.

What does the Kubernetes Horizontal Pod Autoscaler scale?

The number of pod replicas. The Horizontal Pod Autoscaler (HPA) adds or removes replicas according to configured metrics, within its minimum and maximum counts. For example, it can add web-server pods when CPU utilization rises.

m-16-1-1 · Åpne dette flashcardet

What does the Kubernetes Vertical Pod Autoscaler adjust?

The CPU and memory resources requested for containers. The Vertical Pod Autoscaler (VPA) recommends or applies new sizes based on usage. Applying them can require replacing pods, depending on the configured update policy.

m-16-3-1 · Åpne dette flashcardet

What does a Kubernetes PodDisruptionBudget limit during node maintenance?

How many matching application pods may be evicted during voluntary disruption, such as draining a node. A PodDisruptionBudget (PDB) helps maintenance keep enough replicas available. It cannot prevent an unexpected node failure.

prep-aks-015 · Åpne dette flashcardet

What is a Kubernetes StatefulSet used for?

Workloads needing stable pod identities and usually separate persistent storage per pod, such as database members. A StatefulSet gives pods predictable names and supports ordered rollout behavior. The application must still manage its own data replication and recovery.

prep-aks-023 · Åpne dette flashcardet

What does a Kubernetes NodePort Service expose?

A port on the cluster’s nodes. Traffic sent to a reachable node IP and that port is forwarded to the Service’s pods. The client still needs network/firewall access to the node.

m-09-2-1 · Åpne dette flashcardet

What does a Kubernetes LoadBalancer Service provision?

A cloud load balancer that forwards traffic to the Service, when the cluster’s cloud integration supports it. Its frontend can be public or private, depending on configuration.

m-09-3-1 · Åpne dette flashcardet

What does a Kubernetes ExternalName Service return?

A DNS alias, called a CNAME, pointing to the hostname configured in externalName. Clients resolve that name and connect to the destination. The Service does not proxy the connection.

m-09-4-1 · Åpne dette flashcardet

Is Kubernetes Ingress a Service type?

No. Ingress is a separate Kubernetes resource for routing HTTP/HTTPS requests to Services by hostname or URL path. An ingress controller must implement those routing rules; merely creating an Ingress object does not provide a working controller.

m-09-5-1 · Åpne dette flashcardet

What are the default Deployment rolling-update maxSurge and maxUnavailable values?

Both default to 25% for RollingUpdate. maxSurge allows extra pods and rounds up; maxUnavailable allows unavailable pods and rounds down. With three desired replicas, that permits one extra pod and zero unavailable pods during the update.

m-10-1-1 · Åpne dette flashcardet

What are the default DaemonSet rolling-update surge and unavailability settings?

maxUnavailable defaults to 1 and maxSurge to 0. The DaemonSet normally replaces pods gradually, allowing one unavailable pod without creating extra surge pods.

m-10-2-1 · Åpne dette flashcardet

What are the default AKS node-pool upgrade surge and unavailability settings?

One surge node and maxUnavailable=0. AKS can add one temporary node before draining an old node. These are node-pool upgrade defaults; your configuration and available capacity can change how the upgrade proceeds.

m-10-3-1 · Åpne dette flashcardet

What happens when a Kubernetes liveness probe fails repeatedly?

The node’s kubelet agent stops the container once the failure threshold is reached. It then follows the pod’s restart policy; a normal Deployment container is restarted. Use liveness to detect a process that needs restarting.

m-11-1-1 · Åpne dette flashcardet

How can a pod consume a Kubernetes Secret without embedding its value in the pod manifest?

Reference a separately created Secret in the pod specification. Use env.valueFrom.secretKeyRef to populate an environment variable, or mount the Secret as a volume. The pod manifest contains the Secret name and key, rather than the credential value. Protect access to the Secret itself; base64 encoding is not encryption.

What resource setting is needed for CPU-utilization-based HPA scaling?

CPU requests on the relevant containers. The HPA expresses CPU utilization as a percentage of the requested CPU, so it needs that baseline. Resource metrics, normally supplied by metrics-server, must also be available.

m-16-2-1 · Åpne dette flashcardet

When does the Kubernetes cluster autoscaler add nodes?

When a pod cannot be scheduled and adding a node in an eligible pool would make room for it. The pool must be below its configured maximum. Constraints unrelated to missing node capacity, such as incompatible placement rules, may need a different fix.

m-16-4-1 · Åpne dette flashcardet

Why can KEDA wake a workload from zero replicas when CPU-only scaling cannot?

KEDA can scale from external work signals such as messages waiting in a queue. It can therefore detect demand while no app replica is running. CPU-only scaling needs a running pod to produce CPU measurements.

How do you inspect logs from a container's previous crashed instance?

Run kubectl logs <pod-name> --previous. For a multi-container pod, add -c <container-name>. This requests logs from that container’s previous terminated instance in the pod, when those logs are still available. Without --previous, you normally read the current instance’s logs.

How do you find why a Pending Kubernetes pod cannot be scheduled?

Read the scheduler’s events with: kubectl describe pod <pod-name> Look for FailedScheduling. It can identify insufficient CPU/memory, placement-rule conflicts, taints or storage claims that are not ready. Fix the reported constraint.

What runs in an AKS system node pool?

Critical cluster components such as CoreDNS and metrics-server. AKS system pools use Linux. They prioritize system workloads; use scheduling controls if application pods should be kept off those nodes.

Which kubectl operation evicts workloads for node maintenance while respecting disruption budgets?

Use kubectl drain <node-name>, with appropriate options such as --ignore-daemonsets. It marks the node unschedulable and evicts eligible pods, normally respecting PodDisruptionBudgets. Check workloads, storage and disruption budgets first; drain can wait or fail if those constraints cannot be satisfied.

What does kubectl cordon do to existing pods?

kubectl cordon <node-name> marks the node unschedulable for new ordinary pod placements. Existing pods keep running. Use drain, not cordon alone, when you also need to evict workloads for maintenance.

Which Azure CLI command stops an eligible AKS cluster while preserving its configuration?

Run: az aks stop --resource-group mygroup --name mycluster Replace the names with a cluster that supports stop/start. Its configuration is retained so it can later be started again. Storage and other retained resources can still cost money.

How can an AKS node pool refresh its operating-system image without choosing a new Kubernetes version?

Use a node-image-only upgrade. For example: az aks nodepool upgrade --resource-group mygroup --cluster-name mycluster --name userpool --node-image-only This refreshes that pool’s node image without selecting a new Kubernetes version. It still rolls nodes, so plan for workload disruption and replacement capacity.

How do ResourceQuota and LimitRange differ in Kubernetes?

ResourceQuota limits aggregate use in a namespace, such as total requested CPU or the number of certain objects. LimitRange sets defaults and/or allowed ranges for individual objects, such as container CPU and memory requests and limits. A quota is a namespace budget; a limit range constrains each applicable object.

What does Kubernetes imagePullPolicy: Always check at container startup?

At startup, the kubelet resolves the image reference through the registry to obtain its digest. If content with that digest is already cached, it can reuse the local layers. Always therefore checks the registry, but does not mean every image layer is downloaded again on every start.

Why is a toleration alone insufficient to require GPU placement?

A toleration permits a pod to run on a node with a matching taint; it does not require that node. Use a node selector or node affinity to require the intended GPU node pool. A workload that actually uses a GPU must also request the appropriate GPU resource, such as nvidia.com/gpu.

How does Microsoft Entra Workload ID authenticate an AKS workload?

The pod receives a Kubernetes service-account token. Microsoft Entra validates the configured trust for that token and exchanges it for an access token representing the associated Azure identity. The identity’s roles then determine which Azure services it may access.

Which Kubernetes resource controls network traffic into or out of pods?

A NetworkPolicy. It selects pods and defines allowed incoming and/or outgoing network connections. The cluster’s network implementation must enforce NetworkPolicy for those rules to take effect.

How is native Kubernetes read-only access limited to one namespace?

Create a Role containing the needed read verbs, such as get, list and watch, and bind it to the user or service account with a RoleBinding in that namespace. This grants the specified namespaced access without automatically granting the same permissions across the whole cluster.

How does Azure CNI Overlay reduce VNet address consumption?

Pods receive addresses from a separate pod address range instead of consuming one address each from the node subnet. This reduces the virtual network addresses needed for a large number of pods; the nodes still use subnet addresses.

What does a Deny Azure Policy admission rule do to a non-compliant Kubernetes workload?

It rejects the resource request when the configured policy applies and enforcement is enabled. The non-compliant resource is not admitted to the cluster. An Audit rule would report the issue instead.
