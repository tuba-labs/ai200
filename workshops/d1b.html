Praktisk oppgave8 tilknyttede kort

Rull ut, finn en feil tag og rull tilbake

  1. Opprett namespace ai200-v2. Rediger bare den nye kopien av deployment.yaml: sett image til AI200_IMAGE. Apply er avgrenset til dette namespace-et.
  2. Vent på rollout, kall /health med port-forward, og noter podnavn og image-digest. Skaler til to podder.
  3. Sett en ugyldig image-tag, bruk describe/events og finn ImagePullBackOff. Kjør rollout undo og bekreft at /health virker igjen. Bruk logs --previous bare når en tidligere containerinstans faktisk finnes.
# Opprett et eget namespace etter at du har kontrollert kubectl-context.
kubectl create namespace ai200-v2
# Bruk manifestet med ditt tilgjengelige image.
kubectl apply -n ai200-v2 -f workshops/labs/containers/deployment.yaml
# Vent på at utrullingen blir klar.
kubectl rollout status -n ai200-v2 deployment/workshop-api
# Se hendelser og containerstatus.
kubectl describe pods -n ai200-v2
# Gjør helseruten tilgjengelig lokalt; la denne terminalen stå åpen.
kubectl port-forward -n ai200-v2 deployment/workshop-api 8088:8080
Vis kildefil: containers/deployment.yaml

Last ned filen. Rediger bare kopien under workshops/labs/.

# Bruk Kubernetes-API-et for Deployment-ressurser.
apiVersion: apps/v1
# En Deployment vedlikeholder ønsket antall pod-replikaer.
kind: Deployment
# Metadata identifiserer selve Deployment-ressursen.
metadata:
  # Bruk dette navnet i kubectl rollout, logs og scale.
  name: workshop-api
# Beskriv ønsket tilstand for Deployment-en.
spec:
  # Start med én pod; senere skalerer du til to.
  replicas: 1
  # Velg hvilke pods Deployment-en skal styre.
  selector:
    # Match podenes labels nøyaktig.
    matchLabels:
      # Selectoren må passe med labelen i pod-malen under.
      app: workshop-api
  # Denne malen brukes til å opprette hver pod.
  template:
    # Dette er metadata for podene, ikke for Deployment-en.
    metadata:
      # Sett labels som Deployment og Service kan velge etter.
      labels:
        # Bruk samme app-label som selectoren over.
        app: workshop-api
    # Beskriv innholdet i hver pod.
    spec:
      # Denne poden inneholder én applikasjonscontainer.
      containers:
        # Gi containeren et navn i podens logger og status.
        - name: api
          # Bytt til hele ACR-adressen og taggen du skal teste.
          image: ai200-api:v2
          # Hent imaget hvis noden ikke allerede har denne taggen lokalt.
          imagePullPolicy: IfNotPresent
          # Dokumenter portene containeren lytter på.
          ports:
            # Appen lytter på port 8080 inne i containeren.
            - containerPort: 8080
          # Angi ressursbehov og øvre grenser for containeren.
          resources:
            # Scheduler bruker disse behovene ved plassering på en node.
            requests:
              # Be om 0,1 CPU-kjerne.
              cpu: 100m
              # Be om 64 MiB minne.
              memory: 64Mi
            # Sett øvre grenser for containerens ressursbruk.
            limits:
              # Begrens CPU-bruken til 0,25 kjerne.
              cpu: 250m
              # Minnegrensen er 128 MiB; overskridelse kan avslutte containeren.
              memory: 128Mi
          # Avgjør om poden er klar til å motta tjenestens trafikk.
          readinessProbe:
            # Bruk en HTTP-forespørsel som readiness-kontroll.
            httpGet:
              # Denne stien skal gi et vellykket HTTP-svar.
              path: /health
              # Send kontrollen til appens containerport.
              port: 8080
            # Vent to sekunder før første readiness-kontroll.
            initialDelaySeconds: 2
            # Gjenta kontrollen hvert femte sekund.
            periodSeconds: 5
Forventet resultat og forklaring

En fungerende utrulling, en forklart feil og en bekreftet rollback. Et ImagePullBackOff skyldes ikke automatisk CPU-mangel.

# Bruk autoscaling-API-et som støtter mål for ressursutnyttelse.
apiVersion: autoscaling/v2
# Beskriv en horisontal pod-autoskalerer.
kind: HorizontalPodAutoscaler
# Identifiser skaleringsressursen.
metadata:
  # Navnet gjelder bare i valgt namespace.
  name: workshop-api
# Definer hva og hvordan det skaleres.
spec:
  # Pek på Deployment-ressursen som skal få flere eller færre replikaer.
  scaleTargetRef:
    # Bruk samme API-versjon som Deployment-en.
    apiVersion: apps/v1
    # Målressursen er en Deployment.
    kind: Deployment
    # Navnet må passe med manifestet i samme mappe.
    name: workshop-api
  # Behold minst én replika i dette eksemplet.
  minReplicas: 1
  # Avgrens demoen til tre replikaer.
  maxReplicas: 3
  # Bruk en ressursmåling, ikke en ekstern kølengde.
  metrics:
    # Velg poddenes CPU-måling.
    - type: Resource
      # Beskriv ressurs og mål.
      resource:
        # CPU er målingen vi ønsker.
        name: cpu
        # Sammenlign bruken med poddenes CPU requests.
        target:
          # Utilization er en andel av requests.
          type: Utilization
          # Målverdien er 50 prosent, med fungerende ressursmålinger.
          averageUtilization: 50
