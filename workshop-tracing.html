Følg Kom i gang før økten.

Tidsanslaget gjelder med verktøy og eventuelle ressurser under «Klargjør før økten» klare. Python-øvelsene bruker samme .venv i prosjektroten. Kommandoene starter i prosjektroten der ikke annet er angitt.

Bruk egne labressurser og rydd opp etter bruk. Kostnadsveiledning (valgfritt).

Før du starter · 10 min

.\.venv\Scripts\Activate.ps1
python -m pip install -r labs/observability/requirements.txt

services.py kjører enten frontend på 8091 eller backend på 8092. Start dem i to terminaler, begge fra prosjektroten. Uten connection string eksporteres spans til konsollen.

1. Start to tjenester · 10 min

python labs/observability/services.py backend

I den andre aktiverte terminalen:

python labs/observability/services.py frontend

I en tredje terminal:

Invoke-RestMethod http://localhost:8091/process

Forventet: status 200 og en trace-ID. Finn samme ID i begge konsollene.

2. Følg foreldre og kontekst · 15 min

Finn SERVER-spannet i frontend, CLIENT-spannet call-backend og SERVER-spannet i backend. Trace-ID er felles; span-ID-ene er ulike og ParentId kobler dem. Finn inject på senderen og extract på mottakeren. Fjern inject i en lokal kopi, restart frontend og sammenlign. Sett den tilbake etter testen.

3. Finn treghet og feil · 15 min

Invoke-RestMethod "http://localhost:8091/process?delay=0.4"
curl.exe -i "http://localhost:8091/process?fail=1"

Forventet: tregere span og deretter HTTP 500 med error-status på berørte spans. Finn hvor feilen oppstår, og skill den fra symptomene i frontend.

4. Send til Azure og rydd opp · 10 min

Forbered en Application Insights-ressurs med tilknyttet workspace før neste økt. Stopp begge tjenester og sett denne variabelen i begge aktiverte terminaler:

$env:APPLICATIONINSIGHTS_CONNECTION_STRING = "LIM-INN-DIN-CONNECTION-STRING"

Start backend og frontend igjen og gjenta kallene. Koden eksporterer både spans og egendefinerte request-/duration-målinger. Avslutt med Ctrl+C slik at eksportørene får flush.
