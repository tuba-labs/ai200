Bygger på: 4. Miljøer og revisjoner i Container Apps.

Gjennomføringstiden er ikke målt. Sett av tid til å forklare valgene og prøve egne varianter. Følg klargjøringen i denne delen før oppgavene. Python-øvelsene bruker samme .venv i prosjektroten. Start kommandoene i prosjektmappen du åpnet i IntelliJ, der ikke annet er angitt.

Bruk egne labressurser og rydd opp etter bruk. Kostnadsveiledning (valgfritt).

Før du starter

Start med Container App-en fra del 4. Hvis den er slettet, følg opprettelsesstegene der først. Kjør fra prosjektroten i en innlogget PowerShell-terminal. Bytt gruppenavn og eventuelt appnavn til dine verdier.

$rg = "DIN-DOMENE-1-GRUPPE"
$ca = "ai200-api"
$location = az containerapp show --resource-group $rg --name $ca --query location -o tsv
$storage = "ai200q" + (New-Guid).ToString("N").Substring(0, 12)
az containerapp revision set-mode --resource-group $rg --name $ca --mode single -o none
az storage account create --resource-group $rg --name $storage --location $location --sku Standard_LRS --kind StorageV2 --allow-blob-public-access false -o none
$queueConnection = az storage account show-connection-string --resource-group $rg --name $storage --query connectionString -o tsv
az storage queue create --name scale-demo --connection-string $queueConnection -o none
az containerapp secret set --resource-group $rg --name $ca --secrets "queue-connection=$queueConnection" -o none
az storage queue exists --name scale-demo --connection-string $queueConnection --query exists -o tsv

Kontrollpunkt: siste kommando viser true. I portalen: åpne Container App-en → Secrets og finn navnet queue-connection. Storage-kontoen er en egen labkonto i samme labgruppe; noter navnet til regel og opprydding. Tilkoblingsstrengen inneholder en kontonøkkel og skal bare ligge i terminalvariabelen og apphemmeligheten. Ved ny terminal: sett $storage til det eksisterende kontonavnet og hent $queueConnection på nytt, uten å opprette en ny konto.

Testappen demonstrerer skalering; den leser ikke meldinger fra køen. Microsoft Learn: opprette Storage-konto, opprette kø og skaleringsregler.

1. Lag en KEDA-regel

I Scale: min 0, maks 2, Custom rule med typen azure-queue. Metadata: queueName=scale-demo, accountName lik Storage-kontoen og queueLength=5. Knytt autentiseringsparameteren connection til hemmeligheten queue-connection. Lagre og finn revisjonen som ble opprettet.

2. Gi køen arbeid

Legg 15 små meldinger i labkøen med kommandoene under. I portalen: åpne Container App-en → Monitoring → Metrics og velg Replica Count. Undersøk også systemloggen i Log stream. Med terskel 5 tilsier 15 meldinger tre replikaer, men maksgrensen er 2. Vent gjennom polling og oppstart. Ved null aktivitet: sjekk kønavn, forbindelse og systemlogger.

1..15 | ForEach-Object {
    az storage message put --queue-name scale-demo --content "lab-$_" --connection-string $queueConnection -o none
}

3. Fjern arbeid og observer

Tøm bare labkøen med kommandoen under. Observer at nedskalering tar tid. Sammenlign pollingintervallet med cooldown; disse er ulike mekanismer. Diskuter hva som ville skjedd om en ekte worker fullførte meldingene underveis.

az storage message clear --queue-name scale-demo --connection-string $queueConnection -o none

Rydd opp

Åpne labgruppen i portalen. Etter skaleringsforsøket: slett Container App-en, miljøet, identiteten ai200-ca-pull og Storage-kontoen du noterte. Sletting av appen fjerner dens skaleringsregel og hemmelighet; sletting av Storage-kontoen fjerner labkøen. Behold ACR til del 6 er ferdig. Ikke slett gruppen mens den fortsatt inneholder ACR eller andre ressurser du skal bruke. Fjern tilkoblingsstrengen fra terminalen:

Remove-Variable queueConnection -ErrorAction SilentlyContinue
