Bruk egne labressurser og rydd opp etter bruk. Kostnadsveiledning (valgfritt).

Før du starter · 10 min

Opprett en Cosmos DB for NoSQL-labkonto og databasen workshop uten delt throughput. Skriptet oppretter hver labcontainer med 400 RU/s. Vektorsøket i neste økt støtter ikke shared throughput. Bruk en egen labkonto. Ha endpoint og en lokal labnøkkel klar. Kontoen brukes også i workshop 10–11.

.\.venv\Scripts\Activate.ps1
python -m pip install -r labs/cosmos/requirements.txt
$env:COSMOS_ENDPOINT = "https://DIN-KONTO.documents.azure.com:443/"
$env:COSMOS_KEY = "DIN-LAB-NOKKEL"
$env:COSMOS_DATABASE = "workshop"

1. Opprett og hent dokumenter · 15 min

python labs/cosmos/demo.py setup
python labs/cosmos/demo.py query
python labs/cosmos/demo.py point

demo.py bruker /topic som partisjonsnøkkel og skriver request charge. Sammenlign spørringen med point read. Forventet: note-1 og note-2 fra query, note-1 fra point. Noter RU; tallene varierer.

2. Endre en indekseringspolicy · 15 min

Undersøk policyen for notes: embedding-feltet er utelatt fra vanlig indeksering. Kjør SQL i Data Explorer med query metrics på. På den lille labcontaineren: ekskluder /text/? fra policyen og vent på fullført transformasjon. Kjør en spørring på topic og sammenlign med søk på text. Rett policyen tilbake etterpå.

Målet er å se hvilke felter som støttes effektivt av en indeks. Tre dokumenter gir ikke grunnlag for store ytelseskonklusjoner.

3. Velg consistency bevisst · 10 min

Undersøk kontoens consistency og klientens session-håndtering. Sammenlign Session, Eventual og Strong i portalen og den offisielle beskrivelsen. Noter hvilke konsistenskrav en chat-historikk og en statistikkvisning kan ha. Hvis du endrer labkontoens standard, kjør oppslagene igjen og noter RU. Et vellykket enkeltoppslag demonstrerer ikke alle garantiene.

Rydd opp · 10 min

Behold kun labkontoen hvis du fortsetter til workshop 10–11. Ellers slettes den. Fjern COSMOS_KEY fra terminalen når økten er ferdig; sett den på nytt ved neste økt.
