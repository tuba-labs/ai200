Før du starter

Docker med Linux-containere må kjøre. Start i prosjektroten og gå til labs/containers. app.py er ferdig testkode; Dockerfile er filen du skal forstå.

Set-Location labs/containers
docker version

1. Bygg et image

docker build -t ai200-api:v1 .
docker image ls ai200-api

Finn base-image, arbeidsmappe, COPY, bruker og CMD i Dockerfile. Forklar hvilke filer som bygges inn. Forventet: en lokal tag ai200-api:v1.

2. Kjør og feilsøk

docker run --detach --name ai200-api --publish 127.0.0.1:8080:8080 ai200-api:v1
Invoke-RestMethod http://localhost:8080/health
curl.exe -i http://localhost:8080/missing
docker logs --tail 20 ai200-api

Forventet: 200 fra /health og 404 fra /missing. Prosessen fortsetter å kjøre. Forklar hvorfor EXPOSE og portbindingen har ulike oppgaver.

3. Versjoner og tilbakerulling

Endre standardverdien for APP_VERSION fra v1 til v2 i app.py. Den gamle containeren beholder sin kopi til den erstattes.

docker build -t ai200-api:v2 .
docker stop ai200-api
docker rm ai200-api
docker run --detach --name ai200-api --publish 127.0.0.1:8080:8080 ai200-api:v2
Invoke-RestMethod http://localhost:8080/health

Forventet: v2. Gjenta med taggen v1 og bekreft v1. Et image bør kunne identifiseres entydig.

Rydd opp og forklar

docker stop ai200-api
docker rm ai200-api

Behold kildefilene og de lokale imagene til neste økt. Forklar forskjellen mellom en filendring, et nytt image og en ny container.

Sett standardverdien APP_VERSION tilbake til v1 i kildefilen før workshop 2.
